Три способи розширити Jarvis

02 · Plugin API

API плагінів

Плагін — це звичайний Python-файл. Jarvis імпортує його, читає список TOOLS і реєструє кожен інструмент для моделі. Маніфесту й збірки немає.

Де лежать плагіни

Windows%APPDATA%\Jarvis\plugins
macOS~/Library/Application Support/Jarvis/plugins
Linux~/.local/share/Jarvis/plugins

Завантажуються файли з розширенням .py. Файли, назви яких починаються з підкреслення, пропускаються. Код верхнього рівня виконується під час імпорту, тому тримай його легким і не відкривай мережеві з'єднання там.

plugins/notes.py 
# A minimal plugin: one tool, one file.
TOOLS = [{
    "type": "function",
    "function": {
        "name": "note_add",
        "description": "Add a local note.",
        "parameters": {
            "type": "object",
            "properties": {
                "text": {"type": "string", "description": "Note text"}
            },
            "required": ["text"],
        },
    },
}]

def run(name, args, ctx):
    if name != "note_add":
        return "Unknown tool."
    text = str(args.get("text", "")).strip()
    if not text:
        return "Nothing to save."
    path = ctx.data_dir / "notes.txt"
    with path.open("a", encoding="utf-8") as fh:
        fh.write(text + "\n")
    ctx.log(f"note_add: {len(text)} chars")
    return f"Saved: {text}"

Контракт

НазваТипЗначення
TOOLSlist[dict]OpenAI-style схеми функцій. Кожен елемент має містити function.name і function.parameters.
run(name, args, ctx)functionВикликається з назвою інструмента, розібраними аргументами й контекстом плагіна. Повертай рядок; винятки показуються моделі як помилка інструмента.
handlefunctionНеобов'язковий аліас для run(). Якщо є обидва, перемагає run().

Назви інструментів мають бути унікальними. Якщо плагін оголошує вже наявну назву, Jarvis пропускає цей інструмент і пише рядок у журнал. Некоректні схеми й зламані імпорти пропускаються без падіння застосунку.

Контекст плагіна

ЧленЩо робить
ctx.confirm(action, detail="")Показує діалог підтвердження й повертає True, лише якщо користувач згоден. Використовуй перед видаленням файлів, надсиланням даних або зміною системи.
ctx.log(text)Пише рядок у журнал і UI Jarvis.
ctx.run(tool_name, args)Викликає інший зареєстрований інструмент і повертає результат.
ctx.cfgЗнімок поточних налаштувань лише для читання.
ctx.data_dirШлях до папки даних Jarvis. Використовуй для стану плагіна.
ctx.plugins_dirШлях до папки плагінів.

Перезавантаження й життєвий цикл

Плагіни завантажуються на старті. Після додавання або редагування файлу скажи «перезавантаж плагіни» або виклич інструмент plugin_reload. Jarvis прибирає старі інструменти плагінів, повторно імпортує кожен файл і реєструє новий набір. Якщо плагіни вимкнені в Налаштуваннях, завантажувач одразу виходить.

Плагіни не в пісочниці.

Плагін виконується з тими самими правами, що й Jarvis. Встановлюй лише код, якому довіряєш, читай його перед запуском і використовуй ctx.confirm для руйнівних дій. Плагін може читати файли, ходити в мережу й запускати процеси.

03 · Mobile bridge

API Android-мосту

Міст — це необов'язковий HTTPS-сервер усередині Jarvis. Він стартує лише коли ти натискаєш «ANDROID: ПІДКЛЮЧИТИ» в бічній панелі, і зупиняється, коли вимикаєш його або закриваєш застосунок. Він розрахований на довірену локальну мережу, а не на доступ з інтернету.

Що ти отримуєш

Один або кілька LAN-URL на кшталт https://192.168.1.10:8765, випадковий bearer-токен і SHA-256 відбиток самопідписаного сертифіката. Android-застосунок використовує токен для кожного запиту чату й може закріпити відбиток.

Ендпоінти

МетодШляхАвторизаціяПризначення
GET/healthНемаєПовертає {service: JARVIS, status: ready}. Зручно для перевірки доступності.
POST/api/chatBearer <token>Приймає промпт, режим і коротку історію; повертає відповідь моделі.
curl · /health + /api/chat 
# Health check (no token). -k accepts the self-signed certificate.
curl -k https://192.168.1.10:8765/health

# Chat request.
curl -k https://192.168.1.10:8765/api/chat \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"text":"Hello","mode":"natural","history":[]}'

# Response
# {"reply":"..."}

Будь-хто в тій самій мережі з токеном може надсилати промпти твоєму Jarvis. Не роби port-forward для 8765, не використовуй публічний Wi-Fi і вимикай міст, коли закінчив. Сертифікат самопідписаний, тому порівнюй відбиток, а не довіряй наосліп.

04 · AI-провайдери

Jarvis має прямі інтеграції, каталог OpenRouter і локальні моделі Ollama. Список моделей — це суміш курованих прямих моделей і живих OpenRouter ID. Додай хоча б один ключ; додай кілька, щоб failover був корисним.

Як працює failover

  1. Jarvis надсилає запит спочатку обраній моделі.
  2. Якщо ключ відсутній, провайдер повертає помилку авторизації/квоти, мережа таймаутить або відповідь непридатна, Jarvis пробує наступну налаштовану модель.
  3. Перемикання тихе: ти отримуєш відповідь, а не стіну помилок провайдерів. Журнал показує, хто відповів і хто впав.
  4. Якщо впали всі налаштовані провайдери, ти отримуєш одну зрозумілу помилку з останньою причиною.

Ключі лежать у config.json у папці даних Jarvis. Вони надсилаються лише обраному провайдеру — проксі Jarvis і телеметрії немає.

05 · Офлайн-режим

Офлайн-режим і локальний голос

Увімкни офлайн-режим у Налаштуваннях — і Brain спілкується лише з локальними моделями Ollama. Хмарні ключі ігноруються, тож нічого не виходить за межі машини. Якщо Ollama не запущена або модель не завантажена, Jarvis покаже зрозумілу помилку, а не піде тихо в мережу.

КлючТиповоЗначення
offline_modefalseВикористовувати лише локальні моделі Ollama.
offline_modelollama/llama3.2Основна локальна модель; підходить будь-яка назва Ollama, наприклад ollama/qwen2.5:7b.
offline_ollama_urlhttp://127.0.0.1:11434/v1/chat/completionsOpenAI-сумісний endpoint Ollama.
stt_backendautoauto, google або offline. Офлайн-режим примусово використовує локальний STT.
tts_backendautoauto або offline. Офлайн-режим примусово використовує локальний TTS.
offline_stt_binaryпорожньоШлях до whisper-cli (або сумісного бінарника).
offline_whisper_modelпорожньоШлях до моделі ggml-*.bin.
offline_tts_binaryпорожньоШлях до виконуваного файлу Piper.

Налаштування локального мовлення

  1. Завантаж whisper.cpp (whisper-cli) і ggml-модель, наприклад ggml-base.bin.
  2. Завантаж Piper і український або англійський голос .onnx.
  3. Відкрий Налаштування → Офлайн-режим, встав шляхи до обох бінарників і моделей, потім натисни «Перевірити».
  4. Постав STT і TTS в offline (або залиш auto) і перевір мікрофон.
Бінарники не входять у збірку.

Jarvis не завантажує whisper.cpp чи Piper автоматично. Без них офлайн-режим усе ще відповідає на текстові запити через Ollama, але розпізнавання мовлення й озвучення недоступні. В офлайн-режимі Jarvis не переходить на хмарні STT чи TTS.

06 · Пам'ять і автоматизації

Пошук у пам'яті й задачі за розкладом

Як працює пошук у пам'яті

Кожен збережений запис отримує 384-вимірний локальний embedding із слів, біграм і триграм символів через хешування BLAKE2b. Вектор детермінований, не потребує завантаження моделі й не виходить за межі машини. Коли ти надсилаєш запит, Jarvis ранжує записи за косинусною схожістю й додає вісім найрелевантніших, а не останні тридцять.

  • Старі записи memory.json отримують embeddings автоматично під час першого використання.
  • У менеджері пам'яті є поле семантичного пошуку; результати ранжуються локально.
  • Це лексико-семантичний пошук, а не нейромережа. Він добре працює з відмінками й одруками, але не розуміє глибоких перефразувань.

Розклади автоматизацій

ПрикладКоли запускається
once 2026-12-31T23:59Одноразово в конкретний локальний час.
daily 09:00Щодня о 09:00 за локальним часом.
weekly mon 09:00Щопонеділка о 09:00; українські назви днів теж працюють.
every 30mКожні 30 хвилин, мінімум 5 хвилин.

Дії навмисно обмежені: prompt надсилає текст асистенту, notify показує нагадування й озвучує його. Автоматизації зберігаються в automations.json і не можуть виконувати свавільні shell-команди. Створюй їх у вкладці «Автоматизації» або інструментами automation_create, automation_list і automation_cancel.

Без фонового демона.

Планувальник працює всередині процесу Jarvis кожні 20 секунд. Якщо Jarvis закритий, автоматизації не запускаються; пропущені одноразові задачі лишаються вимкненими, повторювані — чекають наступного відповідного слота.

07 · Marketplace

Marketplace плагінів

Marketplace — це локальний JSON-реєстр, а не сервер. Jarvis читає assets/marketplace/registry.json, перевіряє кожен запис, звіряє байти плагіна з SHA256 і просить підтвердження перед копіюванням файлу в папку плагінів. Авто-встановлення й тихого оновлення немає.

registry.json 
{
  "version": 1,
  "plugins": [{
    "id": "hello-market",
    "name": "Hello Market",
    "version": "1.0.0",
    "description": "Minimal example plugin.",
    "author": "JARVIS",
    "file": "hello_market.py",
    "sha256": "d589eacaeab41f7cb9b604cc2631a723ac61361efa8594b811c024fdf3ada47d",
    "tags": ["example", "hello"]
  }]
}

Процес встановлення

  1. Перевірка id, назви, імені файлу, версії й формату SHA256.
  2. Відхилення файлів понад 512 КБ, не-.py назв і будь-якого path traversal.
  3. Хешування джерела й порівняння з реєстром; розбіжність скасовує встановлення.
  4. Показ назви, версії, опису й префікса хешу в діалозі підтвердження.
  5. Атомарне копіювання в папку плагінів і перезавантаження реєстру плагінів.
Хеш — не гарантія безпеки.

SHA256 доводить, що файл відповідає реєстру, а не що код безпечний. Плагіни працюють із тими самими правами, що й Jarvis, і не ізольовані пісочницею. Читай код перед встановленням, особливо якщо реєстр нестандартний.

08 · Roblox MCP

Roblox Studio через MCP

На Windows Jarvis підключається до офіційного Roblox Studio MCP. Він не втручається в клієнт Roblox і не використовує експлойти. Studio має бути відкрите, а MCP-сервер — доступний.

Перезапуск приватного сервера

Встанови roblox_private_server у config.json на URL налаштування приватного сервера. Коли просиш Jarvis перезапустити сервер, він відкриває цю сторінку й просить підтвердження. «Shutdown All Servers» ти натискаєш у Roblox сам; Jarvis не автоматизує клієнт Roblox.

09 · Кастомізація

Кастомізація інтерфейсу

Вкладка «Кастомізація» — у бічній панелі (✦). Вона змінює справжній інтерфейс, а не макет: кольори, порядок блоків, шрифти, анімації й необов'язковий кастомний блок із живим прев'ю. Зміни зберігаються в customization.json і застосовуються без перезапуску.

Контракт кастомного коду

Блок коду має визначати build(parent, colors) і повертати Tkinter-віджет. Прев'ю оновлюється автоматично після короткої паузи. Доступні імена: tk, ttk, parent, colors, root і math.

custom code · build() 
def build(parent, colors):
    card = tk.Frame(parent, bg=colors["panel"])
    tk.Label(
        card,
        text="CUSTOM MODULE",
        bg=colors["panel"],
        fg=colors["accent"],
        font=("Consolas", 8, "bold"),
    ).pack(anchor="w", padx=14, pady=(12, 2))
    tk.Label(
        card,
        text="This block is built by your code.",
        bg=colors["panel"],
        fg=colors["text"],
        font=("Segoe UI", 10),
    ).pack(anchor="w", padx=14, pady=(0, 12))
    return card
Обмежені builtins, а не справжня пісочниця.

render_custom_code обмежує доступні імена для сніпета, але Python не є безпечною пісочницею. Запускай лише свій код або код, який ти прочитав і зрозумів.

Збережені налаштування лежать у %APPDATA%\Jarvis\customization.json на Windows, ~/Library/Application Support/Jarvis/customization.json на macOS і ~/.local/share/Jarvis/customization.json на Linux.

10 · Безпека

Модель безпеки

  • Local-first: чати, налаштування, ключі й дані плагінів лежать у папці даних Jarvis. Акаунта або хмари Jarvis немає.
  • Небезпечні дії на ПК потребують підтвердження. Катастрофічні PowerShell-патерни блокуються до виконання.
  • Android-міст використовує випадковий bearer-токен і HTTPS із самопідписаним сертифікатом. Він вимкнений за замовчуванням.
  • Плагіни й кастомний код — це довірений локальний код, а не пісочниці. Перевіряй перед запуском.
  • Відгуки — публічні GitHub issues. Не додавай у відгук паролі, API-ключі чи особисті дані.
  • Збірки непідписані. Перевіряй SHA256 і GitHub-атестації перед запуском завантаженого файлу.
  • docs/CODE_SIGNING.md — повний гід із підпису й перевірки збірок із командами для Windows, macOS і Linux.
Що виходить із твого ПК

Лише запити, потрібні для функцій, які ти викликаєш: промпти до обраного AI-провайдера, вебпошук, запити до Home Assistant, виклики Roblox Studio MCP і запити до GitHub API для оновлень і відгуків. Прихованого endpoint телеметрії немає.

11 · Проблеми

Що робити, якщо не працює

«Hey Jarvis» не будить асистента

Увімкни wake word у Налаштуваннях, дозволь доступ до мікрофона й перевір, чи його не займає інша програма. Для офлайн-детекції встанови openwakeword: pip install -r requirements-wake.txt. Без нього Джарвіс використовує Google STT і потребує інтернету. Wake word лише починає слухати; команда записується після нього.

Плагін не завантажується

Перевір, що файл закінчується на .py і не починається з підкреслення. Він має визначати TOOLS і викличний run() або handle(). Назви інструментів не повинні збігатися з вбудованими. Увімкни плагіни в Налаштуваннях і виклич plugin_reload. Журнал покаже точну помилку імпорту.

Телефон не бачить міст

Використовуй той самий Wi-Fi, дозволь порт 8765 у фаєрволі, скопіюй URL і токен точно, порівняй відбиток сертифіката. Міст слухає 0.0.0.0, тому VPN або другий мережевий адаптер можуть дати іншу адресу.

Усі моделі падають

Відкрий Налаштування й перевір ключі та квоти. 401 означає поганий ключ; 429 — ліміт частоти. Спробуй іншого провайдера або модель. Журнал покаже, хто пробувався останнім і чому впав.

Інструменти Studio недоступні

Studio MCP працює лише на Windows. Відкрий Roblox Studio, переконайся, що його MCP-сервер запущений, і виклич list_roblox_studios. Якщо список порожній, перезапусти Studio й перевір налаштування MCP.

Мій відгук не з'явився

Сайт читає публічні issues, у тілі яких є маркер відгуку. Після надсилання заповненого issue зачекай хвилину й онови сторінку. Ліміти GitHub API можуть затримати список; посилання «Усі відгуки на GitHub» працює завжди.

Офлайн-голос каже, що не налаштований

Відкрий Налаштування → Офлайн-режим і перевір обидва шляхи до бінарників і обидва шляхи до моделей. whisper-cli потребує моделі ggml-*.bin; Piper — голосу .onnx. Натисни «Перевірити», щоб побачити, що знайдено. Jarvis не включає й не завантажує ці файли. В офлайн-режимі він не переходить на хмарні мовленнєві сервіси.

Marketplace каже, що SHA256 не збігається

Файл плагіна відредагували після генерації реєстру або реєстр застарів. Не обходь перевірку. Перегенеруй хеш із точного файлу й онови registry.json або перевстанови оригінальний файл. Розбіжність означає, що байти, які ти збираєшся запустити, не ті, що переглядали.

Автоматизація не спрацювала

Автоматизації працюють лише коли Jarvis відкритий; фонового сервісу немає. Перевір, що задача ввімкнена, розклад у майбутньому, а наступний запуск видно у вкладці «Автоматизації». Одноразові задачі в минулому лишаються вимкненими. Повторювані — чекають наступного відповідного слота.
